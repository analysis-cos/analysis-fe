# 프로젝트 기획/UX 리뷰 피드백

검토일: 2026-07-05  
검토 범위: 현재 프론트엔드 코드베이스 기준  
대상 제품: 화장품 광고 효용 분석기 / BrandDash Analytics Dashboard

## 1. 총평

현재 제품의 방향은 명확해졌다. 초기에 기능 카드와 페이지가 병렬로 흩어져 있던 구조에서, 지금은 다음의 큰 틀이 잡혔다.

- 요약 대시보드: 담당 브랜드 또는 회사 전체의 상품 포트폴리오 요약
- 선행지표 분석: 선택한 상품 기준의 광고 집행, 소재, 플랫폼 반응 분석
- 후행지표 분석: 같은 분석 기준 상품의 판매 채널 흐름, 랭킹, 가격, 리뷰, 광고 시점 연결
- 올리브영 커머스 분석: 공개 화면 스냅샷과 제한/권한 상태를 구분하는 상세 분석 영역

이 구조는 방향이 맞다. 특히 “선행/후행을 상품 단위로 묶고, 대시보드는 브랜드 전체를 본다”는 IA는 B2B SaaS 분석 제품에서 자연스럽다. 광고 담당자는 회사 전체 현황을 먼저 보고, 이상 징후나 기회 상품을 발견한 뒤 상품 단위로 내려가 선행/후행 관계를 확인할 수 있다.

다만 현재 구현은 아직 “보이는 대시보드” 수준에 가깝고, 실제 분석 제품으로 설득력을 가지려면 몇 가지 기획 축이 더 필요하다. 가장 큰 부족점은 기준 정의, 데이터 출처, 계산 방식, 분석 단위 전환, 액션 근거가 아직 화면 언어와 데이터 모델에서 충분히 분리되어 있지 않다는 점이다.

## 2. 현재 구조의 좋은 점

### 2.1 IA가 단순해졌다

현재 상단 탭은 `요약`, `선행지표`, `후행지표` 3개로 정리되어 있다. 이는 사용자가 “무엇을 봐야 하는가”를 빠르게 이해하기 좋다.

특히 다음 구조는 유지할 가치가 있다.

- 요약: 브랜드/회사 전체
- 선행지표: 상품 단위 광고 집행
- 후행지표: 같은 상품 단위 후행 신호

이 구조는 “전체에서 보고, 상품으로 내려가고, 다시 전체로 돌아온다”는 분석 흐름을 만들 수 있다.

### 2.2 상품 기준 선택 개념이 생겼다

선행지표와 후행지표가 같은 `분석 기준 상품`을 공유하는 구조는 매우 중요하다. 광고 집행과 구매 반응은 캠페인 기준만으로 묶으면 흔들릴 수 있다. 상품 기준이 있어야 플랫폼별 광고, 판매 채널, 리뷰, 랭킹이 하나의 분석 단위로 연결된다.

현재 구현에서는 상품 선택기가 대시보드에서는 숨겨지고, 선행/후행 화면에서만 노출된다. 이 방향은 맞다.

### 2.3 올리브영 분석의 데이터 신뢰도 표현이 좋다

올리브영 영역은 단순 KPI 카드보다 성숙하다.

- 공개 화면 스냅샷
- 계산 지표
- 파트너 데이터 필요
- 수집 제한
- 정확한 판매량/매출/전환율 미포함
- 할인/쿠폰/증정 등 혼선 요인

이런 표현이 들어가 있어, “광고 효과를 단정하지 않는다”는 제품 원칙이 비교적 잘 반영되어 있다.

### 2.4 기능 카드형 IA를 걷어낸 것은 좋은 결정이다

기능을 카드로 나열하고 들어가게 하는 구조는 초기 기획 탐색에는 좋지만, 실제 사용자가 매일 쓰는 운영 화면에는 어색하다. 현재는 소재 성과 비교, 광고 시점 등록, 판매 채널 추이, 가격/혜택 비교 같은 기능이 화면 안에 녹아 들어가 있다.

이 방향은 유지해야 한다.

## 3. 핵심 기획 한계

### 3.1 “브랜드 전체”와 “상품 단위”의 전환 규칙이 아직 약하다

현재 구조상 대시보드는 브랜드 전체, 선행/후행은 상품 단위다. 하지만 사용자가 대시보드에서 특정 상품을 클릭했을 때 어떤 일이 일어나는지가 아직 기획적으로 명확하지 않다.

현재는 상품 클릭 시 상세 패널이 뜨고, 분석 기준 상품도 바뀐다. 하지만 사용자는 다음 중 무엇을 기대해야 하는지 헷갈릴 수 있다.

- 상품 상세 정보 보기
- 선행지표 분석으로 이동
- 후행지표 분석으로 이동
- 해당 상품을 기준 상품으로 설정

권장 방향:

- 대시보드 상품 행 클릭은 “상품 기준으로 분석하기” 액션임을 명확히 해야 한다.
- 행 클릭 대신 명시적 버튼을 둘 수 있다.
  - `이 상품 분석`
  - `선행 신호 보기`
  - `후행 신호 보기`
- 상세 패널과 분석 기준 변경은 분리하는 편이 좋다.

### 3.2 브랜드 전체 요약 KPI의 정의가 모호하다

대시보드의 `집행 광고비`, `구매 건수`, `평균 ROAS`는 현재 개발용 수치로만 존재한다. 실제 제품에서는 이 KPI가 어떤 범위를 의미하는지 반드시 정의되어야 한다.

필요한 기준:

- 기간: 최근 7일, 최근 30일, 캠페인 기간, 사용자 지정 기간
- 상품 범위: 담당 브랜드 전체, 선택 브랜드, 즐겨찾기 상품, 캠페인 연결 상품
- 채널 범위: 전체 광고 플랫폼, 전체 판매 채널, 특정 플랫폼만
- 데이터 출처: 광고 플랫폼 데이터, 판매 채널 데이터, 수동 업로드, 파트너 데이터
- 계산 방식: ROAS 분모와 분자, 구매 반응 산식, 중복 구매 처리

현재 화면에서는 “구매 건수”와 “ROAS”가 실제 거래/전환 데이터처럼 보일 위험이 있다. 파트너 데이터가 없는 상태라면 대시보드에서도 “연동 데이터 기준” 또는 “수동 업로드 기준” 같은 출처 표시가 필요하다.

### 3.3 선행/후행 연결의 핵심인 “기간 윈도우”가 부족하다

광고 이후 판매 채널 흐름을 보려면 기간 창이 중요하다.

예:

- 광고 당일
- D+1
- D+3
- D+7
- D+14
- 캠페인 시작 전 7일 baseline
- 캠페인 종료 후 7일 holdout

현재 화면은 01.08~01.14 형태의 고정 날짜 데이터가 많다. 실제 분석에서는 다음이 필요하다.

- 기준일 선택
- 캠페인 전/후 기간 설정
- 광고 시점별 이벤트 마커
- 변화량 산식 표기
- 기준일 데이터가 없을 때의 fallback

특히 “광고 시점 등록”은 좋은 기능이지만, 아직 후행 분석의 기간 계산과 연결되어 있지 않다. 광고 시점을 등록하면 D+1/D+3/D+7 변화가 자동으로 갱신되는 구조가 필요하다.

### 3.4 “상품군” 개념이 아직 약하다

화장품 커머스에서는 같은 상품이 옵션, 용량, 기획세트, 리뉴얼, 플랫폼별 상품 ID로 나뉜다. 현재는 `Product.rank` 하나가 사실상 식별자 역할을 한다.

실제 제품에서는 최소한 다음 개념이 필요하다.

- Master Product: 내부 기준 상품
- Platform Product: 올리브영/쿠팡/네이버별 상품
- Product Group: 옵션, 세트, 용량, 리뉴얼을 묶은 상품군
- Campaign Product Mapping: 어떤 캠페인이 어떤 상품 또는 상품군을 대상으로 했는지
- Brand Product Portfolio: 브랜드 전체 상품 목록

이 개념이 없으면 후행지표가 흔들린다. 예를 들어 광고는 “크림 80ml”를 홍보했는데 올리브영 후행 신호는 “크림 80ml 기획세트”에 잡히는 일이 흔하다.

### 3.5 “광고 효용”의 판단 단계가 부족하다

현재 화면은 숫자와 일부 해석을 보여주지만, 사용자가 최종적으로 무엇을 판단해야 하는지 단계가 더 필요하다.

권장 판단 단계:

1. 광고 집행이 있었는가?
2. 선행 신호가 충분했는가?
3. 후행 신호가 같은 기간에 움직였는가?
4. 가격/쿠폰/증정/품절 등 혼선 요인이 있었는가?
5. 선행 신호와 후행 신호의 연결 신뢰도는 어느 정도인가?
6. 다음 액션은 무엇인가?

현재 화면에는 1~4는 일부 존재하지만, 5와 6이 약하다. 특히 “신뢰도”는 올리브영 섹션에는 있지만 대시보드/선행/후행 전체에는 없다.

## 4. 화면별 피드백

## 4.1 요약 대시보드

현재 역할: 브랜드 또는 회사 전체 요약.

좋은 점:

- 상품 하나가 아니라 전체 포트폴리오를 보는 방향으로 정리된 점이 좋다.
- KPI, 추이, 캠페인 요약, 상품별 연결 현황으로 큰 틀이 잡혀 있다.
- “상품별 선행·후행 연결 현황”은 대시보드에서 상품 단위 분석으로 내려가는 진입점으로 적절하다.

보완점:

- 대시보드에는 “분석 기준 상품”이 없어야 한다. 현재 구조상 숨겨져 있어 방향은 맞다.
- KPI의 근거와 범위가 필요하다.
- 캠페인 요약이 아직 브랜드 전체인지, 상품군별인지, 캠페인별인지 혼합되어 있다.
- “구매 건수”와 “ROAS”가 실제 거래액 기반인지 개발용/추정/연동 데이터인지 표시가 없다.
- 대시보드에서 상품을 클릭했을 때 상세 패널을 열지, 상품 분석 화면으로 이동할지 명확히 해야 한다.

권장 개선:

- 대시보드 상단에 기간 필터 추가:
  - 최근 7일
  - 최근 30일
  - 캠페인 기간
  - 사용자 지정
- KPI 카드 하단에 데이터 출처 표시:
  - 광고 플랫폼 연동
  - 판매 채널 연동
  - 수동 업로드
  - 데모 데이터
- 상품별 연결 현황의 액션을 버튼으로 명확히 분리:
  - `선행 분석`
  - `후행 분석`
  - `상품 상세`
- “브랜드 전체”를 나타내는 헤더 보강:
  - 담당 브랜드
  - 관리 상품 수
  - 연결된 광고 캠페인 수
  - 연결된 판매 채널 수

어색한 문구:

- `구매 건수`: 데이터 출처가 명확하지 않으면 파트너 구매 데이터가 있는 것처럼 보일 수 있다.
  - 대안: `판매 채널 반응`, `연동 구매 건수`
- `평균 ROAS`: 실제 광고비와 거래액 데이터가 모두 있어야 가능하다.
  - 대안: `ROAS 추정`, `연동 ROAS`, `광고비 대비 반응`

## 4.2 선행지표 분석

현재 역할: 분석 기준 상품의 광고 집행/소재/플랫폼 반응 분석.

좋은 점:

- 상단의 공통 상품 선택기를 통해 후행지표와 같은 상품을 바라본다.
- 캠페인 추가와 URL 등록이 있어 실제 운영 입력 흐름이 있다.
- 소재 성과 비교, 콘텐츠 유형별 액션, 크리에이터 후보, 콘텐츠 보관함이 기능 카드가 아니라 화면 안에 녹아 있다.

보완점:

- 광고 플랫폼 데이터 모델이 너무 단순하다.
  - spend, impressions, clicks, engagements만 있다.
  - 실제 광고 분석에서는 CPM, CPC, CTR, CPV, view rate, completion rate, frequency 등이 필요할 수 있다.
- “참여율”이 어떤 산식인지 명확하지 않다.
- 캠페인과 상품의 연결 근거가 없다.
  - 직접 광고 대상 상품인지
  - 랜딩 페이지 상품인지
  - 콘텐츠에서 언급된 상품인지
  - 브랜드 캠페인이라 간접 연결인지
- URL을 넣는 기능은 있으나 URL 검증, 플랫폼 자동 판별, 중복 URL 처리, 캠페인명 자동 추천이 없다.
- 등록한 캠페인이 후행지표의 광고 시점 이벤트와 자동으로 연결되지 않는다.

권장 개선:

- 캠페인 등록 시 다음 필드를 명확히 받기:
  - 캠페인명
  - 플랫폼
  - 광고/콘텐츠 URL
  - 시작일
  - 종료일
  - 대상 상품 또는 상품군
  - 목표 판매 채널
  - 집행비
- 광고 지표 정의를 화면에 짧게 표시:
  - CTR = 클릭 / 노출
  - 참여율 = 참여 / 노출
  - 저장률, 완주율 등은 플랫폼별로 다르게 정의
- 캠페인 목록에서 후행 연결 상태를 표시:
  - 연결됨
  - 상품 매핑 필요
  - 판매 채널 데이터 없음
  - 기간 기준 없음

어색한 문구:

- `소재 메시지 참고`: 실제 기능이 단순 추천인지 저장된 참고 콘텐츠인지 더 명확히 나눌 필요가 있다.
  - 대안: `소재 메시지 후보`
- `브랜드 언급 모니터`: 데이터 출처가 없으면 SNS 모니터링처럼 보인다.
  - 대안: `콘텐츠 내 브랜드 언급`
- `콘텐츠 보관함`: 괜찮지만 실제 저장/삭제/분류 기능이 없으면 임시 화면처럼 보인다.
  - 대안: 기능이 생기기 전에는 `소재 후보 목록`

## 4.3 후행지표 분석

현재 역할: 같은 분석 기준 상품의 판매 채널 흐름 분석.

좋은 점:

- 광고 시점을 차트에 직접 표시하는 방향은 매우 좋다.
- 올리브영/쿠팡/네이버를 같은 화면에서 보는 구조는 광고 담당자가 이해하기 쉽다.
- 가격, 혜택, 리뷰, 랭킹 같은 혼선 요인을 같이 보는 방향이 좋다.

보완점:

- `거래액`, `전환율`, `ROAS`, `구매 건수`가 데이터 출처 없이 너무 직접적으로 표시되면 위험하다.
  - 파트너/광고주 데이터가 있다는 전제가 없으면 위험하다.
  - 올리브영 섹션에서는 조심스럽게 표현하는데, 후행지표 상단에서는 더 단정적으로 보인다.
- 채널별 데이터가 모두 같은 품질로 보인다.
  - 실제로 올리브영, 쿠팡, 네이버는 가져올 수 있는 데이터와 정확도가 다르다.
- 광고 시점 등록과 구매 흐름 차트가 연결되어 보이지만, 실제 산식이나 변화 계산은 없다.
- “가격·혜택 조건 비교”가 모든 채널에 동일하게 적용되는지 불명확하다.
- 상품명 검색이 분석 기준 상품 화면에 남아 있어 모순이 생길 수 있다.
  - 분석 기준 상품만 보는 화면이라면 검색은 불필요하다.
  - 여러 상품을 비교하는 화면이라면 분석 기준 상품이라는 설명이 약해진다.

권장 개선:

- 후행지표 상단 KPI 명칭과 출처 표시:
  - `구매 건수`
  - `매출` → `거래액`
  - `전환율` → `연동 전환율` 또는 `방문 대비 구매 비율`
  - `ROAS` → `연동 ROAS`
- 채널별 데이터 신뢰도 표시:
  - 올리브영: 공개 화면 스냅샷
  - 쿠팡: 수동 업로드/파트너 데이터 필요
  - 네이버: 검색/상품 데이터/광고 데이터 분리
- 광고 시점 등록 후 자동 계산 카드 추가:
  - 광고 전 7일 평균
  - 광고 후 3일 변화
  - 광고 후 7일 변화
  - 혼선 요인 여부
- 분석 기준 상품 화면이면 검색창 제거 또는 `채널 결과 필터`로 변경.

어색한 문구:

- `판매 채널 분석`: 좋다.
- `랭킹·구매 반응 점검`: “점검”은 괜찮지만, 운영 툴 느낌이 강하다.
  - 대안: `채널별 반응 요약`
- `가격·혜택 조건 비교`: 좋다.
- `채널별 랭킹 변화`: 좋다.
- `광고 연결`: 어떤 광고와 연결되었는지 모호하다.
  - 대안: `연결 광고`, `관련 캠페인`, `광고 시점`

## 4.4 올리브영 커머스 분석

현재 역할: 올리브영 공개 화면 스냅샷 기반 상세 분석.

좋은 점:

- 데이터 신뢰도 배너가 명확하다.
- PARTNER_ONLY/UNSUPPORTED/DERIVED 구분이 있다.
- 정확한 판매량/매출/전환율 미포함 문구가 있다.
- 랭킹, 리뷰, 할인율, 프로모션 상태를 구분한다.
- 혼선 요인을 광고 효용 해석과 함께 보여준다.
- 지표 커버리지 매트릭스가 있어 “무엇을 가져올 수 있는지”를 설명한다.

보완점:

- 선행지표 화면 하단에 올리브영 분석이 들어가 있어 IA가 약간 애매하다.
  - 선행지표는 광고 집행 분석이고, 올리브영은 후행/커머스 성격이다.
  - 현재는 “광고 분석 상세 안에 올리브영 섹션”이라는 이전 요구 때문에 들어간 것으로 보인다.
- 전체 후행지표 화면과 올리브영 상세 모듈의 관계가 중복될 수 있다.
- 올리브영 상세 분석이 다른 채널보다 훨씬 정교해 보여서, 쿠팡/네이버가 상대적으로 미완성처럼 보인다.

권장 개선:

- 올리브영 상세 분석은 후행지표 화면 안으로 이동하는 것을 검토.
- 또는 선행지표 화면에서는 “후행 연결 미리보기”만 보여주고, 상세는 후행지표로 이동.
- 쿠팡/네이버에도 최소한 다음 수준의 구조를 맞춰야 한다.
  - 데이터 출처
  - 수집 가능 지표
  - 제한 지표
  - 가격/리뷰/랭킹 또는 검색 노출
  - 광고 시점 이후 변화
- 올리브영만 상세한 이유를 명시:
  - “현재 올리브영 상세 분석만 제공”
  - “쿠팡/네이버는 연동 예정”

## 4.5 상품 상세/패널

현재 상품 클릭 시 상세 패널 또는 상세 페이지로 이동하는 흐름이 있다.

보완점:

- 대시보드에서 상품 클릭이 “상세 보기”인지 “분석 기준 상품 설정”인지 혼재될 수 있다.
- 상품 상세가 현재 광고/후행 분석과 얼마나 연결되는지 약하다.
- 상세 페이지가 단순 상품 정보에 머물면 분석 제품의 핵심 흐름에서 벗어날 수 있다.

권장 개선:

- 상품 상세에는 다음 탭을 두는 것이 좋다.
  - 기본 정보
  - 연결 캠페인
  - 판매 채널 매핑
  - 랭킹/리뷰 변화
  - 가격/혜택 이력
  - 데이터 출처
- 대시보드 상품 row에는 명시적 액션을 넣는다.
  - `상품 분석 열기`
  - `상세 정보`
  - `캠페인 연결`

## 5. 데이터/모델링 한계

### 5.1 현재 Product 타입이 너무 얕다

현재 `Product`는 다음 필드 중심이다.

- rank
- name
- brand
- category
- price
- change
- imageUrl
- url

실제 서비스에서는 부족하다.

필요한 확장:

- productId
- brandId
- productGroupId
- platformMappings
- canonicalName
- aliases
- status
- launchedAt
- discontinuedAt
- categoryPath
- optionGroup
- volume/size
- sourcePlatform

### 5.2 Campaign 타입도 부족하다

현재 선행 캠페인은 프론트 내부 개발용 데이터에 가깝다.

필요한 확장:

- campaignId
- sourcePlatformCampaignId
- objective
- startAt/endAt
- budget
- actualSpend
- creativeIds
- landingUrl
- targetProductIds
- targetProductGroupIds
- targetCommerceChannels
- attributionWindow
- createdBy/uploadSource

### 5.3 Commerce 데이터의 출처 구분이 전체 화면에 퍼져 있지 않다

올리브영 모듈에는 출처/정확도/제한 표시가 있지만, 대시보드와 후행지표 화면에는 아직 약하다.

필요한 공통 개념:

- DataSourceBadge
- DataAvailability
- AccuracyGrade
- lastUpdatedAt
- partnerDataRequired
- manualUploadRequired
- computedMetric

이 개념이 모든 화면에 동일하게 들어가야 신뢰도가 올라간다.

### 5.4 개발용 데이터와 실제 데이터의 경계가 약하다

현재 개발용 데이터는 UI를 보여주는 데 충분하지만, 실제 서비스 데이터처럼 보이게 만드는 위험이 있다.

문제:

- 일부 숫자가 실제 데이터처럼 보인다.
- 거래액/전환율/ROAS가 파트너 데이터 전제 없이 노출된다.
- 캠페인과 상품 연결이 실제 매핑처럼 보인다.

권장:

- 개발 환경에서는 데모 데이터와 실제 데이터를 명확히 분리.
- 운영 환경에서는 데이터 없을 때 “연동 필요” 상태 표시.
- 개발용 fixture는 운영 화면에 노출되지 않게 분리.

## 6. UX/문구 한계

### 6.1 “반응”이라는 표현은 좋지만 너무 넓다

현재 `구매 흐름`, `후행 신호`, `선행 신호` 같은 완곡한 표현을 많이 쓴다. 단정 표현을 피하려는 의도는 좋다. 그러나 너무 많이 쓰이면 사용자가 실제 지표를 이해하기 어렵다.

권장:

- 카드 제목은 지표명으로 명확히:
  - 광고비
  - 클릭
  - 참여율
  - 랭킹 변화
  - 리뷰 수 변화
  - 할인율 변화
- 설명 문장에서 “반응” 사용:
  - “구매 건수는 연동된 판매 채널 데이터 기준입니다.”

### 6.2 “구매”, “거래액”, “전환율”, “ROAS”는 출처 없이는 위험하다

올리브영 정책 원칙과 충돌할 수 있다.

화면에서 사용할 때는 다음 중 하나가 필요하다.

- 연동 데이터 기준
- 수동 업로드 기준
- 파트너 데이터 기준
- 데모 데이터
- 추정값

권장 문구:

- `연동 구매 반응`
- `광고주 제공 거래액`
- `수동 업로드 거래액`
- `연동 ROAS`
- `데모 ROAS`

피해야 할 문구:

- `실제 매출`
- `광고로 구매 증가`
- `광고 효과`
- `전환 개선`

### 6.3 CTA가 부족하다

현재 화면은 분석 정보를 보여주지만, 사용자가 다음에 무엇을 해야 하는지 명확한 버튼이 부족하다.

필요한 CTA:

- 상품 분석 열기
- 광고 시점 추가
- 캠페인 연결
- 판매 채널 데이터 연결
- CSV 업로드
- 리포트 만들기
- 액션 메모 추가

## 7. 화면 구성/정보 밀도 피드백

### 7.1 요약 대시보드

현재 정보 순서:

1. 히어로
2. KPI
3. 광고비/구매 흐름
4. 판매 채널 반응
5. 캠페인 요약
6. 상품별 연결 현황
7. 상품별 테이블

권장 순서:

1. 브랜드 전체 KPI
2. 상품별 선행·후행 연결 현황
3. 캠페인별 요약
4. 판매 채널 반응
5. 상품별 상세 테이블

이유:

- 대시보드는 “무엇을 먼저 봐야 하는지”가 중요하다.
- 큰 차트보다 상품별 이상/기회 목록이 먼저 와야 실제 업무에 가깝다.

### 7.2 선행지표

현재 정보 순서:

1. 상품 기준 헤더
2. KPI
3. 소재 성과 비교
4. 메시지/브랜드/크리에이터
5. 캠페인 추가/필터
6. 집행 추이/채널별 집행
7. 캠페인 목록
8. 올리브영 상세 모듈

권장:

- 캠페인 추가는 너무 위에 있지 않아도 된다.
- 기본 사용자는 먼저 현황을 보고, 필요할 때 추가한다.
- 올리브영 상세는 후행 쪽으로 이동하거나 접힘 처리 권장.

### 7.3 후행지표

현재 정보 순서:

1. 상품 기준 헤더
2. KPI
3. 판매 채널 분석
4. 판매 채널별 구매 흐름 추이
5. 광고 시점 등록
6. 채널별 효율
7. 채널별 결과 테이블

권장:

- 광고 시점 등록은 분석 입력 기능이므로 차트 바로 옆에 있는 것은 좋다.
- 다만 “등록”과 “분석 결과”가 시각적으로 같은 무게라서 혼동될 수 있다.
- 등록 패널은 오른쪽 보조 영역 또는 drawer가 더 자연스럽다.

## 8. 기능적으로 빠진 핵심 요소

우선순위 높은 순서로 정리한다.

### P0. 데이터 출처/정확도 공통 표시

대시보드와 후행지표에도 올리브영처럼 데이터 출처와 정확도 표시가 필요하다.

### P0. 상품군/플랫폼 상품 매핑

선행/후행 연결의 핵심이다. 이게 없으면 실제 데이터에서 광고 상품과 판매 채널 상품이 어긋난다.

### P0. 기간 기준과 baseline

광고 전/후 변화를 보려면 기준 기간이 필요하다. 현재는 고정 날짜 데이터다.

### P1. 캠페인-상품-판매 채널 연결 상태

캠페인이 어떤 상품과 어떤 판매 채널에 연결되어 있는지 상태가 필요하다.

예:

- 연결 완료
- 상품 매핑 필요
- 판매 채널 데이터 없음
- 기준일 데이터 없음
- URL 확인 필요

### P1. 액션 관리

분석 후 다음 액션을 기록하고 담당자를 지정하는 기능이 필요하다.

예:

- 소재 추가
- 예산 조정
- 상세페이지 수정
- 쿠폰 영향 분리
- 리뷰 확보

### P1. 리포트/공유

B2B SaaS에서는 분석 결과를 내부 공유해야 한다.

필요:

- PDF/이미지 export
- 캠페인 리포트
- 상품별 요약
- 코멘트/메모

### P2. 알림

나중 단계로 좋다.

예:

- 광고 집행 후 D+3 후행 신호 없음
- 랭킹 급락
- 할인율 급변
- 부정 리뷰 증가
- 경쟁 상품 랭킹 상승

## 9. 기술/구현 한계

### 9.1 데이터가 대부분 컴포넌트 내부 상수다

현재 개발용 데이터가 화면 컴포넌트 내부에 많다. 제품이 커질수록 유지보수가 어렵다.

권장:

- `features/media`
- `features/commerce`
- `features/dashboard`
- `fixtures`
- `adapters`

이렇게 분리하는 것이 좋다.

### 9.2 API adapter 경계가 올리브영에만 있다

올리브영은 adapter/fixture/type 구조가 좋다. 같은 패턴을 대시보드, 선행, 후행에도 적용해야 한다.

### 9.3 테스트 범위가 올리브영 중심이다

현재 테스트는 올리브영 정책/유틸 검증에 치우쳐 있다. 새 IA에서는 다음 테스트가 필요하다.

- 대시보드에는 상품 선택기가 보이지 않는다.
- 선행/후행에는 상품 선택기가 보인다.
- 선행/후행이 같은 selectedProductRank를 사용한다.
- 대시보드의 KPI가 특정 상품명이 아니라 브랜드 전체 문구를 사용한다.
- 후행지표의 거래액/전환율 문구가 데이터 출처 없이 과장되지 않는다.

### 9.4 접근성 보완

차트가 많은 화면이므로 텍스트 요약이 필요하다.

필요:

- 차트 caption
- 표 caption
- 버튼 aria-label
- 외부 링크 rel 처리: 현재 일부는 잘 되어 있음
- keyboard focus 스타일

### 9.5 성능 보완

현재는 규모가 작아 문제 없지만, 실제 데이터가 들어오면 차트와 테이블이 무거워질 수 있다.

필요:

- 테이블 pagination
- 최근 30일/90일 토글
- 차트 lazy loading
- 이미지 lazy loading
- 큰 리스트 memoization

## 10. 우선순위 로드맵 제안

### 1단계: 제품 구조 안정화

- 대시보드 = 브랜드 전체
- 선행/후행 = 상품 기준
- 상품 선택 후 선행/후행 이동 흐름 명확화
- 상품 상세와 상품 분석 액션 분리

### 2단계: 데이터 신뢰도 공통화

- 모든 KPI에 데이터 출처 표시
- 거래액/구매/전환율/ROAS 출처 표시
- 개발용 데이터/연동/수동 업로드 구분

### 3단계: 선행-후행 연결 모델 강화

- CampaignProductMapping 추가
- ProductGroup 추가
- PlatformProductMapping 추가
- 광고 시점 기반 D+1/D+3/D+7 변화 계산

### 4단계: 화면 정교화

- 대시보드 상품별 연결 현황을 상단으로 올리기
- 후행지표에서 분석 기준 상품 검색창 제거 또는 목적 변경
- 올리브영 상세 위치 재검토
- 쿠팡/네이버 최소 상세 패널 추가

### 5단계: 운영 기능 추가

- 액션 메모
- 담당자/상태
- 리포트 export
- 알림 조건

## 11. 결론

현재 제품은 방향을 잘 잡았다. 특히 “대시보드는 브랜드 전체, 선행/후행은 상품 기준”이라는 구조는 유지해야 한다. 이 구조가 제품의 중심축이다.

다만 아직은 개발용 데이터 기반 화면이 실제 분석 제품처럼 보이기 시작한 단계라, 다음 세 가지를 먼저 보완해야 한다.

1. 데이터 출처와 정확도 표시를 전체 화면으로 확장
2. 상품군/플랫폼 상품 매핑 모델 도입
3. 광고 전후 기간 기준과 변화 계산 방식 명확화

이 세 가지가 잡히면, 지금의 화면은 단순 대시보드가 아니라 “광고 집행과 판매 채널 흐름을 상품 기준으로 연결해주는 B2B SaaS 분석 제품”으로 설득력이 생긴다.
